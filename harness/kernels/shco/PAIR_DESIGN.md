## Work actually removed

SHX v2 processes one 64-row by 128-feature unit per worker ticket. Its A staging, immutable weight staging and scale staging are repeated for another row unit at the same feature tile. Within one unit it already reuses weights across its rows; this experiment only joins two different row units. It does not call two different N tiles or two different experts the same weight.

For one projection, `stage_mma2` consumes a 64-row A tile, 2,048 weight bytes and 256 scale bytes per stage. A paired CTA owns two original row bands, stages each A separately, and issues the immutable B/S copies only once. Both bands then read that same shared-memory B/S stage. Weight format and layout do not change, and no separate weight representation is created.

For the 3712 by 2688 up matrix, packed NVFP4 bytes are 3712*2688/2 = 4,988,928. FP8 scale bytes are 3712*2688/16 = 623,616. The down matrix has the transposed dimensions and the same counts. One complete B/S pass through both matrices is therefore 11,225,088 bytes. Joining only two row-band pairs changes eight original row-unit passes to six passes. At most 22,450,176 bytes, approximately 21.41 MiB, of source-level global B/S requests are deleted per eligible full shared-expert layer. This is 25% of that specific request stream, not 25% of all shared-expert traffic, whole prefill time, decode time or score.

These counts are conditional on this branch actually being selected and executing. Existing feature-major units may already obtain B/S from L2, and requests from different workers may merge. The byte count is not an HBM reduction, a measured bandwidth requirement or a latency estimate. All arithmetic, A traffic, output traffic and the original chain-0 scratch remain. Additional staging resources and an extra launch per projection may cost more than the removed B/S requests.

## Why exactly these two pairs

The original host program first splits M496 into 448 rows and a separate 48-row tail. The first launch is seven 64-row bands. Its Marlin partition is computed over the real 48 SMs; changing that partition would change FP32 segment folding.

For up, N3712 gives 29 feature tiles and K2688 gives 42 K64 tiles. Seven row bands give gmn203. The original remainder adjustment produces part2=59, so g<144 has a single segment [0,42]. All feature columns of row bands 0,64,128,192 have g at most 3*29+28=115 and are therefore unsplit.

For down, N2688 gives 21 feature tiles and K3712 gives 58 K64 tiles. gmn147, part2=51, so g<96 is unsplit. Those same four bands have g at most 3*21+20=83 and all use [0,58].

The only pairs are (row0,row64) and (row128,row192), separately at each f0. `_split_pair_units` validates the actual host-produced table for both shapes: exact unit count, unique row/feature keys, nrows64, and the expected one full K segment for every paired unit. Unexpected geometry refuses the feature. Rows256,320,384 and the 48-row tail remain in the original v2 kernel with their original segment lists. No attempt pairs the later bands merely because their row counts look similar.

Up has 232 original units: 58 new pair records plus 116 retained original single records. Down has 168 original units: 42 pair records plus 84 retained singles. Each pair writes the rows of two original units, so every original output row/feature is written exactly once. In a lite final-layer call, `TAIL_ONLY` bypasses pairing completely and runs the original full tail table.

## Thread, stage and scratch ownership

The new kernel has 256 threads, split into two groups of 128. `band=threadIdx.x>>7` selects the row unit. `local_tid=threadIdx.x&127`, local warp, rw, cw and lane retain the original four-warp fragment mapping inside each band. Each thread keeps the same 64 FP32 accumulator elements; the implementation does not place two independent 64-element accumulators in one original thread.

Each stage has A0[4096], A1[4096], B[2048], S[256], totaling 10,496 bytes. Four stages use 41,984 bytes, plus the shared ticket word and implementation alignment. Each region remains 128- and 16-byte aligned as required by the original copy and shared-load instructions. Both bands issue their original two A copies per local thread. Only band0 issues each B copy and its first sixteen local threads issue each S copy. There are no competing B/S writers.

Async-copy wait is per issuing thread. Consequently all threads execute the same commit/wait schedule, every B/S producer performs its own wait, and the full eight-warp CTA barrier follows before either band reads the shared stage. The next iteration's full barrier also protects circular-slot reuse against a slow consumer in either band. Both bands have the identical validated stage count and segment list, so no band takes a different loop exit around these barriers. No cross-CTA spinning, distributed shared memory, new PDL or grid-wide in-kernel synchronization is introduced.

Global scratch is indexed as `(blockIdx.x*2+band)*k2ScratchFloats+local_tid`. Every original scratch element still uses the original stride128; global tid256 must not replace that stride. Each band reserves its original 64 KiB scratch region, including the normally unused R half for a single segment. Pair workers own separate scratch and a separate two-word dynamic counter from the original single workers. The full CTA barrier at the next ticket precedes last-worker counter reset after all output writers finish. Stale scratch is not cached computation: every chain-0 value read has been written for this invocation, and the one-segment pairs never read an old R value.

## Numerical and format boundaries

`stage_mma2` is called unchanged, with the original NVFP4 bit decode, E4M3 scale decode, BF16 scale multiplication, `mma.sync` sequence and fragment ownership. Each band executes its own original ascending K chain0, parks it, resets to positive zero, executes chain1, and combines with the original explicit `__fadd_rn` sequence. No value is reduced between bands. The original global FP32 scale multiplication and BF16 epilogue remain. Up reuses the current BF16x2 ReLU-squared helper; down reuses the ordinary rounded epilogue. The up and down projections are not fused into one arithmetic operation, and the BF16 intermediate is still materialized.

The source preserves the intended operand and instruction chain. That is not proof of compiled device bit identity: register allocation, scheduling, instruction lowering, special values and hardware behavior still require official execution. There is no runtime numerical or speed admission in this draft. The resource gate is explicitly only a resource gate. An official whole run is the first correctness/performance experiment; a complete measured regression beyond the user's threshold must not become a later baseline.

## Resource gate and exact fallback boundary

The optional path requires existing SHCO eligibility, SHX v2, sm121, exactly 48 SMs, M496, one of the two fixed projection shapes, the validated pair tables, contiguous BF16 x/out and matching contiguous prepared int32 NVFP4 weights, E4M3 scales and scalar FP32 global scale. Shapes and devices are checked again on the call. Public up with `relu2=False` selects its up tables by N/K, not by the activation flag. Other shapes, missing ABI, version changes, unsupported alignment or stream mismatches retain the complete original SHX call.

The pair CTA uses its own `(256,1)` launch bound. The original `(128,4)` bound is unchanged. At load time, both new epilogues must report at least 256 allowed threads, no local bytes, 1..128 registers, and static shared memory within the device's default per-block limit. Otherwise no pair storage is published and the original path remains. Pair workers are half the original even worker grid, preserving the aggregate warp budget (18*8 versus current36*4). Odd or too-small worker grids refuse pairing. This is a derived resource bound, not a tuned optimum; per-SM residency and routed contention remain unknown.

The original context is allocated first. Optional tables, scratch and counter are built into local references and published only after all allocations succeed. A recoverable optional CUDA OOM returns the already constructed original context. No launch is attempted as part of that refusal. Other exceptions remain visible. Optional scratch allocation can still change device addresses and allocator behavior; the complete runtime outcome remains unverified.

The first eligible noncapturing call binds pairing to its actual current CUDA stream handle. A capture-time first use with no bound stream declines the optional feature. Any other stream declines it. The tables, scratch, counters and owners exist before capture; there are no request-time private graph captures or allocations for pairing. Fixed shape metadata is cached, never a request result or prompt-dependent weight.

## Stream DAG, graph replay and failure behavior

M496 does not use the separate small-call deferred-down schedule: `_DEFER_MAX_TOKENS` is eight. Existing prefill queues shared up then shared down on its auxiliary stream while the routed path runs, and the existing main/aux join protects consumers. This experiment leaves that entire DAG unchanged. On the same aux stream, each projection queues pair kernel then original single kernel. Only after both complete can the later down/consumer execute. Output is the original fresh BF16 tensor, with disjoint writes rather than a borrowed previous-result cache.

The separate pair counter resets only after all its workers finish. The single queue retains its own original reset. Both are replayed in the captured stream order. The current serial execution and existing aux-stream ownership are required; this does not add a concurrent executor or promise reentrant use of global SHCO contexts. Wrong stream, tail-only and other unsupported calls keep the original operation before any new launch.

After either production launch starts, any native launch error is raised. The code never retries a partially issued pair or single projection through the original full kernel. A capture failure also remains an engine failure; no eager retry is attempted against possibly modified capture or counter state. Refusal is safe only before issuing the new operation, and this document does not claim atomic rollback of an operation that has begun.

The existing SHCO library is one nvcc translation unit. The new header and pair ABI are conditional on `SHX_NO_PAIR`. The official build first attempts the complete library. If it fails or leaves no nonempty library, the build removes the partial artifact and attempts the original library with `SHX_NO_PAIR=1`. If that also fails it preserves the existing nonfatal package-skip behavior and removes the incomplete library. Missing pair symbols cause the Python wrapper to keep original SHX. This fallback occurs only at build/setup before production. It does not hide a runtime launch/capture failure or establish that the new kernel was active.
